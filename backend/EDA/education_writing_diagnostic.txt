4. DATA SCIENCE ROOT CAUSES OF EDUCATION MISCLASSIFICATION
--------------------------------------------------------------------------------
1. Severe Dataset Class Imbalance:
   Writing accounts for 53.59% of training data (716 samples), whereas Education
   accounts for only 9.96% (133 samples) — a 5.38x imbalance ratio. Despite using
   class_weight="balanced", the sheer lexical volume and n-gram diversity of
   Writing enables it to claim generic expository vocabulary.

2. Inconsistent Ground-Truth Annotation (Label Noise):
   Inspection of actual dataset rows shows ambiguous labeling:
   - Writing prompts asking for educational explanations:
     "Please explain the difference between a chemist and a chemical engineer" -> Labeled Writing.
     "Can you provide a brief survey of the major world religions" -> Labeled Writing.
     "Can French Defence initial move defend against four move checkmate? Rationale first" -> Labeled Writing.
   - Education prompts asking for written deliverables:
     "Write blog article comparing The university of manchester mba program to PMP certificate" -> Labeled Education.
     "write a story about The significance of number 127 is part of the Illuminati" -> Labeled Education.
   This mutual cross-contamination prevents the linear model from separating the
   underlying communicative intent from the topic matter.

3. Lack of Specialized Educational Anchors:
   Unlike Coding (which has syntax anchors: 'def', 'class', 'python', 'function')
   or Image Generation ('cinematic', 'render', 'portrait', 'lighting'), Education
   prompts naturally express themselves through plain discursive prose:
   "What is the modulus of Elasticity in its relation to mechanics?"
   "when did the us acquire the last of the territory that would make up the 48 contiguous states?"
   Without specialized lexical anchors, these sentences map into Writing space.

5. INSPECTION OF CODING HEURISTIC IN classifier_service.py
--------------------------------------------------------------------------------
Function inspected: _looks_like_coding_request(text: str)
- Purpose: Keyword rule override for software engineering queries ('react', 'python',
  'javascript', 'function', 'api endpoint', 'sql query', etc.).
- Effect on Education:
  a. It does NOT cause the Education -> Writing error, because its override target
     is strictly 'Coding'.
  b. It can trigger an unintended override from Education -> Coding if an educational
     prompt references programming or technical concepts (e.g., "Explain how the
     python memory manager works to an undergraduate student" will be forced to Coding).
  c. Indentation observation: Line 113 (`confidence = max(confidence, 0.80)`) sets
     an artificial 0.80 confidence floor on ALL predictions regardless of heuristic
     match, which conceals margin ambiguity between Writing and Education.
